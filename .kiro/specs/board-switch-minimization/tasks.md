# 実装計画：Board切替時の最小化改善

設計のBoundary CommitmentsとFile Structure Planを実装範囲の基準とする。各実行サブタスクは1〜3時間を目安とし、必須のテストを任意扱いにしない。チェックを付けるのは、そのタスクの完了条件を確認した後とする。

通常は番号順に進める。2.1と2.2だけは基盤完了後に並列実行でき、記載した依存タスクを満たせば直前の同階層タスクを待たなくてよい。その他は先行する実行タスクの完了を前提とする。

計画レビュー：Task Plan Review Gate通過。Task-Graph Sanity Reviewは独立レビュー（independent）でPASS。1.1〜2.2は実装・検証済み。操作許可契約の補足案は利用者の続行指示で承認済み。

Session本体の変更はSession / Workspace担当一人が逐次所有する。AX担当は診断取得境界、Regression担当はテスト基盤・回帰検証を担当する。共有契約・テスト基盤・ターゲット登録を並列に編集しない。既存の未コミット変更を戻さず、他担当の編集に合わせる。

- [x] 1.1 開発環境と追加部品のビルド登録を整える

  - 共通AX取得結果だけをTree版にも含め、通常版専用の要求管理・保護判定・実行部をTree版へ加えない。未実装の挙動を成功扱いにする仮実装は置かない。
  - 完了時には通常版・Tree版のビルド対象とテスト対象が認識され、追加した空のコンパイル単位による参照切れがないことを確認できる。

  - 完了時には後続の判定・実行・Session・fakeが同じ契約を参照してコンパイルでき、未知の観測と正常結果を区別できる。

  - _Requirements: 3.4, 5.3, 5.4, 5.7, 7.2_

  - 完了時には既存の利用者が引き続きコンパイルでき、旧契約を包む取得が診断能力を保証しないことをテストで確認できる。

- [x] 2.2 (P) 現行の登録保護を理由付きの純粋判断へまとめる
  - 主Board・追加Board・子Board・常設Boardを含む登録保護と、従来の同一ウィンドウ照合を維持する。
  - Terminalの包括保護、曖昧な同一アプリ窓の保護、VS Codeの例外を維持し、対象と除外理由を区別できるようにする。
  - 新しい一覧の同一ID情報を優先し、完全取得時には古い候補を混ぜず、部分失敗時は未確認範囲に限定して既知候補を補う。
  - 状態・AX呼出・永続化を持たせず、共通契約とビルド登録は編集しない。
  - 完了時には登録集合と保護理由、古い同一ID、部分失敗時の補完範囲が専用の純粋テストで確認できる。

- [x] 3. 一要求の背景処理を検証可能にする
- [x] 3.1 表示後に必要な候補を確認し各窓の操作結果を返す

  - 完了時には制御可能なfakeに対し正常操作・状態不明・no-op・部分失敗が別の結果となり、AX呼出がMainActorで行われないことを専用テストで確認できる。

- [x] 3.2 古い操作を区切りで止め実行済み結果を必ず返す
  - 状態読取前と書込直前に有効性を確認し、書込許可には実ウィンドウの識別と復元記録の版を含める。
  - 許可後に実窓や対象判定が変わった場合は再評価し、無効な要求から追加の書込を始めない。
  - すでに開始した同期AX呼出は結果を回収し、成功記録をMainActorへ反映した後に次の操作へ進む。取消・失効・空対象を共通の終了結果へまとめる。
  - 完了時には読取前・書込前の失効と書込中の切替を別々に制御でき、実行済みの成功が返り、失効後の次の書込が発生しないことを確認できる。
  - _Boundary: UnattachedWindowMinimizationExecutor_
  - _Requirements: 3.4, 3.5, 5.4, 7.3_

- [x] 3.3 最新の登録情報で保護と登録復元を再評価する

  - 候補の再分類と実際の操作回数を区別し、再評価だけで集計を二重に増やさない。
  - 完了時には旧登録窓を保護した後で新しい実窓へ差し替えても、旧窓は必要に応じて対象となり、新しい登録窓は保護・復元されることを専用テストで確認できる。

- [x] 4. Sessionの要求・実行枠・復元台帳を整える
- [x] 4.1 統合：新状態へ触れる既存入口のMainActor境界を揃える

  - Status ItemのUIライフサイクルと操作入口を隔離し、既存の画面・Launcherの呼出が同期的な隔離違反を起こさないようにする。
  - 該当する既存テストをメソッド単位で合わせ、共有状態やAXサービスへ新たな無条件の並列共有保証を付けない。
  - 完了時には既存の切替・手動最小化・復元を含む呼出元がコンパイルし、未隔離の同期入口から新状態へ直接アクセスする前提がない。

- [x] 4.2 切替受付と最小化の実行枠を一つの所有者へまとめる
  - 読込み用番号と別の受付世代を切替受付時に更新し、読込み中に待機する要求にも継承する。同一ターゲットでも最新の設定・入口・待機時点・表示情報を採用する。
  - 最新の自動要求を一件、手動と自動を通じた実行枠を一件に保ち、現在の要求だけが枠を解放できるようにする。
  - 成功・失敗・空対象・失効のすべてで最新保留要求を処理し、OFF・空構成は旧要求の失効だけ行う。構成内選択は新たな最小化へ変えない。
  - 手動開始は現在の受付世代へ結び付け、完了済み自動処理を再投入しない。
  - 完了時には状態遷移のテストで最新要求の置換と全終了経路からの引継ぎ、旧完了による枠解除の防止を確認できる。
  - _Boundary: WorkspaceSessionController_
  - _Requirements: 1.3, 1.4, 2.2, 3.1, 3.2, 3.3, 3.4, 4.5_

- [x] 4.3 実際に最小化した記録を画面結果と分けて保持する
  - 正常な非最小化状態からの書込成功を、要求失効後も復元台帳へ反映する。元から最小化済み・状態不明・書込失敗を新しい成功へ数えない。
  - 実窓の識別と記録の版で差分更新し、初回追加順を保って既存の公開一覧へ投影する。
  - 重複した操作結果を二度記帳せず、古い操作の画面・接続・候補更新は現行の受付世代と実行枠で抑止する。
  - 公開一覧への直接代入をやめ、該当する既存テストの準備も記帳入口へ合わせる。
  - 完了時には古い最小化成功が既存の復元対象に残り、古いUI結果は反映されず、同じ成功通知による重複記録がないことを確認できる。
  - _Boundary: WorkspaceSessionController_
  - _Requirements: 3.4, 5.4, 5.6, 5.8, 6.2_

- [x] 4.4 明示復元の結果で新しい記録を消さない
  - 明示復元の開始時に対象記録の版を取り込み、成功または非最小化の正常確認時だけ同じ版を削除する。
  - 状態不明・依然最小化されている復元失敗は記録を保持し、各窓の結果を反映してから次へ進む。一括の失敗配列で全置換しない。
  - 自動の登録復元も同じ台帳差分契約を使い、明示復元に新しい優先順位を導入しない。
  - 完了時には復元中に追加・更新した記録が古い復元結果で消えず、失敗した窓を後から既存操作で再度復元できることを確認できる。
  - _Boundary: WorkspaceSessionController_
  - _Depends: 2.1_
  - _Requirements: 4.2, 5.5, 5.7_

- [ ] 5. 既存操作へ新しい処理を統合する
- [x] 5.1 統合：自動最小化を表示先行の切替処理へ接続する

  - 取得済み結果の再利用と表示後の必要な補完を実行部へ渡し、現在の登録集合による操作許可と結果記帳をSessionへ戻す。
  - 最新設定がOFF・合成参照が空なら新しい補完・最小化・補償復元を起動せず、古い要求の復活を防ぐ。
  - 主画面・Status Item・Launcherの座標、保存、前面化の既存の違いは維持する。
  - 完了時には登録解決がキャッシュだけで終わる切替でも新しい未登録窓へ試行し、補完を止めている間もBoard表示が更新済みであることを確認できる。

  - _Depends: 3.1, 3.2, 3.3, 4.2, 4.3, 4.4_
  - _Requirements: 1.1, 1.2, 1.3, 1.4, 2.1, 2.2, 3.1, 3.3, 6.1, 6.2_

- [ ] 5.2 統合：手動最小化の準備から終了まで切替と協調させる

  - 手動準備中・操作中の新たな切替要求を保持し、成功・失敗・対象なし・失効のすべてから最新要求へ引き継ぐ。
  - 実行済み結果の台帳反映と、手動完了によるbusy・メッセージ・候補更新の有効性を分ける。
  - 完了時には手動の準備や一操作を停止してから切り替えても、最新の自動処理が無言で消えず、古い手動結果が最新状態へ戻らないことを確認できる。
  - _Boundary: WorkspaceSessionController, UnattachedWindowMinimizationExecutor_

- [ ] 5.3 統合：同じ切替の復旧結果を限定した再確認へつなぐ
  - 最新の自動最小化ON・非空として解決済みの要求に限り、既存自動復旧の完了から再確認を要求できるようにする。
  - 固定候補を再分類し、現在の登録を保護・復元する。新たな全列挙や後日のウィンドウ監視へ拡張しない。
  - 保留中の全対象処理を再確認だけの要求で置換せず、同じ切替の失敗数を後続の成功0件で消さない。
  - 完了時には復旧で旧実窓から新実窓へ差し替わっても現在の登録を保護し、OFF時には復旧から新しい最小化処理が生まれないことを確認できる。
  - _Boundary: WorkspaceSessionController, UnattachedWindowMinimizationExecutor_

- [ ] 5.4 統合：待機・処理中・完了の表示とSnapshot連携を揃える
  - 保留と候補確認も含む処理状態をSessionから投影し、古い完了が最新の処理中状態を解除しないようにする。
  - Status Itemが最新の表示用状態を購読し、Board表示済みとウィンドウ処理完了を区別する。新しいパネルや必須操作は作らない。
  - Snapshotは有効な保留・準備・実行中に停止し、最新要求と実行枠が解放された後に再開できるようにする。
  - 既存の最小化前の前面化通知を真の完了通知へ移さず、既存のウィンドウレベル復帰と操作可否を維持する。
  - 完了時には候補確認や古い操作を止めたままでも最新Boardの処理中表示を確認でき、最後の完了後はSnapshotが再開する。
  - _Boundary: WorkspaceSessionController, WindowBoardStatusItemController_
  - _Depends: 4.1, 5.1, 5.2, 5.3_
  - _Requirements: 2.3, 3.4, 5.2, 7.4_

- [ ] 5.5 原因を区別できる低ノイズの診断を接続する
  - 候補数、登録・同一アプリ保護、既に目的状態、成功、失敗、確認不完全を別々に集計する。
  - 古い処理の打切りと最新要求への引継ぎを、対応する切替・操作へ関連付けて記録する。
  - 同じ候補の再判定だけで数を増やさず、同じ切替の後続確認でも既存の失敗記録を保持する。
  - タイトル・文書URLを新たに出力せず、通常の切替に診断閲覧を要求しない。
  - 完了時には診断を観測するテストから候補漏れ・保護・取得/操作失敗・失効を区別でき、古い結果が最新結果を消していないことを確認できる。
  - _Boundary: WorkspaceSessionController_
  - _Depends: 2.1, 2.2, 3.2, 5.3_
  - _Requirements: 5.3, 7.1, 7.2, 7.3, 7.4_
